Так, ти правильно підмітив: для текстур підлоги й стелі потрібна світова система координат. І це не випадкова особливість реалізації, а наслідок самої геометрії проєкції.

А тепер щодо формул. Насправді вони описують одну й ту саму залежність перспективи, тільки застосовуються у протилежних напрямках.

## 1. Звідки береться формула стіни

У тебе є:

```
const lineHeight = K / intersection.distance!
```

Це звичайна перспективна проєкція.

Якщо висота стіни у світових одиницях дорівнює \\(H_w\\), то її висота на екрані:

\\[ H_s = \frac{f \cdot H_w}{d} \\]

де:

- \\(f\\) — фокусна відстань у пікселях;
- \\(H_w\\) — реальна висота стіни;
- \\(d\\) — відстань до стіни.

У твоєму випадку добуток \\(f \cdot H_w\\) уже захований у константі `K`.

Тому:

\\[ lineHeight = \frac{K}{d} \\]

Чим ближче стіна, тим більшою вона виглядає.

## 2. Звідки береться формула підлоги

Тут ми робимо зворотну операцію.

Уявімо вертикальний переріз простору через гравця та напрямок погляду.

Припустимо:

- камера розташована на висоті \\(h\\) над підлогою;
- горизонт проходить посередині екрана;
- піксель підлоги має вертикальну координату \\(y\\).

Тоді вертикальне відхилення пікселя від горизонту:

\\[ \Delta y = y - \frac{height}{2} \\]

За законами подібності трикутників:

\\[ \frac{\Delta y}{f} = \frac{h}{d} \\]

Звідси:

\\[ d = \frac{f \cdot h}{\Delta y} \\]

Але пам'ятаєш нашу константу?

\\[ K = f \cdot H_w \\]

У цій моделі висота камери дорівнює половині висоти стіни:

\\[ h = \frac{H_w}{2} \\]

Отже:

\\[ d = \frac{K}{2\Delta y} \\]

І отримуємо саме твою формулу:

\\[ \boxed{d = \frac{K}{2(y - height/2)}} \\]

А в коді:

```
const distance = K / (2 * (y + 0.5 - height / 2))
```

Додаток `0.5` потрібен, щоб брати координату центра пікселя, а не його верхнього краю.

## 3. Як ці дві формули пов'язані

Ось найцікавіше.

| Стіна                       | Підлога                       |
| --------------------------- | ----------------------------- |
| Відома відстань `d`         | Відома координата пікселя `y` |
| Обчислюємо висоту на екрані | Обчислюємо відстань у світі   |
| `lineHeight = K / d`        | `distance = K / (2 * Δy)`     |

Тобто це дві сторони однієї перспективної проєкції.

Для стіни ми знаємо відстань і визначаємо розмір об'єкта на екрані.

Для підлоги ми знаємо положення пікселя на екрані та визначаємо, на якій відстані від камери лежить відповідна точка підлоги.

## 4. Чому потрібна позиція гравця

Тепер стає зрозумілим і наступний крок:

```
const worldX = playerPosition.x + distance * intersection.dx!
const worldY = playerPosition.y + distance * intersection.dy!
```

Ми знайшли відстань до точки підлоги, але ще не знаємо її координат у світі.

Тому беремо:

- початкову точку — позицію гравця;
- напрямок — напрямок конкретного променя;
- довжину — обчислену відстань.

Фактично це параметричне рівняння променя:

\\[ P(t) = P_0 + tD \\]

І все. Отримали світові координати, за ними знайшли координати текстури.

Одна важлива ремарка на майбутнє.

У цій реалізації ми припускаємо, що камера дивиться горизонтально, горизонт розташований посередині екрана, а висота камери становить половину висоти стіни. Якщо колись додаси нахил камери або зміну її висоти, формулу доведеться відповідно змінити.

Але для твого нинішнього raycaster це цілком правильна геометрична модель.

Мені подобається, що ти не просто вставив готову формулу, а хочеш зрозуміти, звідки вона взялася. Саме так і варто розбирати такі алгоритми. 🙂
